# 상세

## 높음

### 1. 한글 입력 상태에서 대시보드 단축키 동작

- **현상**: 한/영 상태가 한글이면 `r`이 `ㄱ`, `q`가 `ㅂ`처럼 자모로 들어와 단축키가 반응하지 않는다. 화살표, Enter, Esc, 마우스는 영향이 없다.
- **원인**: `panel.py`의 `KEY_COMMANDS`가 입력된 글자로만 명령을 찾는다.
- **개선안**:
  - 두벌식 자모를 같은 자리의 영문 키로 바꾸는 표를 둔다. 쓰는 키만 넣으면 된다.

    | 키 | r | a | x | o | e | q |
    |---|---|---|---|---|---|---|
    | 두벌식 | ㄱ | ㅁ | ㅌ | ㅐ | ㄷ | ㅂ |

  - Windows는 `KEY_EVENT`의 가상 키 코드(`0x41`~`0x5A`)로 판단하는 방법도 있다. 다만 Linux/macOS는 글자만 오므로, 두 OS 모두에 맞는 자모 표가 낫다.
- **범위**: `panel.py` (`command_for`)
- **확인**: 한글 모드에서 각 단축키를 눌러 동작하는지 본다. Windows는 `herdr pane send-text <pane> ㄱ`로도 확인할 수 있다.

### 2. 대시보드 예외 처리와 오류 기록

- **현상**: `DevrunError`가 아닌 예외가 나면 대시보드가 바로 종료된다. pane이 닫히면서 traceback도 사라져 원인을 알 수 없다. 예: herdr 응답 JSON 파싱 실패, 응답에 예상한 키가 없음(`KeyError`).
- **원인**: `Panel.loop`의 `try`가 `DevrunError`만 잡는다. `main`에도 마지막 안전망이 없다.
- **개선안**:
  - 루프 안의 명령 실행과 상태 갱신에서 모든 예외(`Exception`)를 잡는다. 아래 줄에는 한 줄 요약을 보여 주고 루프는 계속 돈다.
  - traceback 전문은 상태 폴더의 `panel.log`에 시간과 함께 남긴다. 파일 크기가 커지지 않도록 최근 N KB만 유지한다.
  - `main`에서 루프 밖으로 나온 예외도 `panel.log`에 남기고 herdr 알림을 띄운 뒤 종료한다.
- **범위**: `panel.py`, 상태 폴더 경로는 `core.state_dir()` 재사용
- **확인**: 일부러 예외를 내는 명령(예: 잘못된 pane id)으로 대시보드가 유지되고 `panel.log`에 기록되는지 본다.

### 3. 중지 대기를 "종료 확인 + 최대 시간"으로

- **현상**: 중지할 때 Ctrl+C 후 **항상 1.5초**를 기다린 뒤 pane/탭을 닫는다.
  - Spring Boot graceful shutdown, DB 연결 정리처럼 1.5초보다 오래 걸리면 정리 도중에 강제로 닫힌다.
  - 금방 끝나는 서비스도 1.5초를 기다린다.
- **원인**: `core.STOP_WAIT_SECONDS` 고정값과 `time.sleep`.
- **개선안**:
  - Ctrl+C를 보낸 뒤 셸(`shell_pid`) 아래 자식 프로세스가 사라질 때까지 0.2초 간격으로 확인한다.
  - 다 사라지면 바로 닫고, 최대 시간이 지나면 그대로 닫는다(남은 프로세스는 pane과 함께 종료).
  - 최대 시간은 서비스별 설정 `stop_timeout`(초, 기본 10)으로 정한다.
  - 전체 중지는 모든 pane에 Ctrl+C를 먼저 보내고 함께 기다린다.
  - Windows `.bat`의 "일괄 작업을 끝내시겠습니까 (Y/N)?" 프롬프트가 떠도 자식 프로세스(java 등)는 이미 끝났으므로 판정에 영향이 없다.
- **설정 형식**: `services[].stop_timeout` (숫자, 선택)
- **범위**: `core.py` (`stop_service`, `down`), `procs.py` 재사용, 문서의 설정 표
- **확인**: 금방 끝나는 서비스는 바로 닫히는지, 종료가 느린 서비스(예: `ping -n 30` + 종료 지연 스크립트)는 끝날 때까지 기다리는지 본다.

### 4. 시작 전에 포트가 이미 사용 중인지 확인

- **현상**: 같은 포트를 다른 프로세스(이전에 띄운 서버, IDE에서 띄운 서버 등)가 쓰고 있으면, 새 서비스가 포트 충돌로 실패해도 대시보드에 **● 실행 중**으로 보인다. 포트에 연결은 되기 때문이다.
- **원인**: 상태 판정이 "자식 프로세스 있음 + 포트 연결됨"만 본다. 그 포트를 누가 열었는지는 모른다.
- **개선안**:
  - 서비스를 시작하기 전에 `port`가 이미 열려 있으면 시작하지 않고 경고한다. 예: "backend: 8080 포트를 이미 다른 프로세스가 쓰고 있습니다." 강제로 시작하는 선택지(대시보드 `Shift+Enter` 등)를 둘지는 반영할 때 정한다.
  - `up`(전체 시작)은 충돌한 서비스만 건너뛰고 나머지는 시작한 뒤, 알림에 건너뛴 목록을 적는다.
- **범위**: `core.py` (`start_service`, `up`), `panel.py` 메시지
- **확인**: `python -m http.server 18765`를 먼저 띄운 뒤 같은 포트 서비스를 시작해 경고가 나오는지 본다.

## 중간

### 5. 대시보드 중복으로 열기 방지

- **현상**: `panel` 액션을 실행할 때마다 대시보드 pane이 새로 열린다.
- **처리**: 프로젝트별 표식 파일에 pane id를 저장한다. 같은 프로젝트의 대시보드 pane이 있으면 그 탭에 포커스를 두고, 없으면 현재 pane 오른쪽에 새 pane을 나눠 셸에서 대시보드를 실행한다. 대시보드가 끝나면 표식 파일을 지워 다음 실행에서 다시 열 수 있다.
- **범위**: `devrun.py` (`open_panel`), `panel.py` 종료 처리
- **확인**: 액션을 반복 실행해 pane 중복이 없는지, Ctrl+C 후 다시 열리는지 확인한다.

### 6. 서비스 목록 스크롤

- **현상**: 서비스가 많아 화면 높이를 넘으면 아래쪽 행이 그려지지 않고, 선택해도 보이지 않는다.
- **개선안**:
  - 목록 영역의 최대 높이를 정한다(예: 화면의 60%). 로그 영역은 최소 3줄을 보장한다.
  - 선택한 행이 항상 보이도록 목록을 스크롤한다. 위아래에 `▲ n개 더` / `▼ n개 더`를 표시한다.
- **범위**: `panel.py` (`draw`, `rows` 좌표 계산)
- **확인**: 서비스 20개짜리 설정으로 작은 pane에서 ↑↓, 휠, 클릭이 맞는 행을 고르는지 본다.

### 7. 로그 미리보기의 줄바꿈 문제

- **현상**: 서비스 pane 폭에서 줄바꿈된 줄이 그대로 여러 줄로 보인다(테스트 중 셸 프롬프트가 두 줄로 나뉘어 보임). 대시보드 폭이 서비스 pane보다 넓어도 미리보기가 좁게 보인다.
- **개선안**: `herdr pane read --source recent-unwrapped`로 원래 줄 그대로 읽고, 대시보드 폭에 맞춰 `fit()`으로 자른다. 긴 줄을 접어서 보여 줄지(여러 줄)는 반영할 때 정한다.
- **범위**: `core.py` (`service_log`)
- **확인**: 긴 로그 줄을 출력하는 서비스로 미리보기를 비교한다.

### 8. 행 선택 시 멈춤 줄이기

- **현상**: 행을 클릭하거나 ↑↓로 선택을 바꿀 때마다 상태 전체를 다시 조회해 0.3~0.5초 멈춘다. herdr CLI를 서비스 수 + 3번 실행하고 프로세스 목록도 조회하기 때문이다.
- **개선안**:
  - 선택이 바뀌면 화면을 바로 다시 그리고, 새 서비스의 로그만 읽는다. 상태는 1초 주기 갱신에 맡긴다.
  - 주기 갱신에서도 `pane process-info`는 상태 파일에 `shell_pid`를 저장해 두고 다시 묻지 않는 방법을 검토한다. pane이 살아 있는 동안 셸 pid는 바뀌지 않는다.
- **범위**: `panel.py` (`move_selection`, `command_for`, `refresh`), `core.py` 상태 형식
- **확인**: 빠르게 ↑↓를 눌러도 선택 표시가 바로 따라오는지 본다.

### 9. 서비스 실행 순서 (`depends_on`)

- **현상**: 전체 시작 시 모든 서비스를 한꺼번에 띄운다. 프론트가 백엔드보다 먼저 떠서 초기 API 호출이 실패하거나, 백엔드가 DB·메시지 브로커를 기다려야 하는 경우를 처리할 수 없다.
- **개선안**:
  - `services[].depends_on`(서비스 이름 목록)을 추가한다.
  - 전체 시작은 의존 순서대로 진행하고, 의존 서비스의 `port`가 열릴 때까지(또는 `port`가 없으면 프로세스가 뜰 때까지) 기다린다. 대기 상한은 `start_timeout`(초, 기본 120)으로 둔다.
  - 대시보드에서는 기다리는 서비스를 "◔ 대기 중"(새 상태 `WAITING`)으로 표시한다. `STATUS_VIEW`에도 추가해야 한다.
  - 순환 의존, 없는 이름은 설정 검증에서 오류로 처리한다.
  - 전체 시작이 오래 걸릴 수 있으므로, 대시보드 입력을 막지 않도록 백그라운드 스레드로 돌릴지 같이 정한다.
- **설정 형식**: `services[].depends_on` (문자열 배열), `services[].start_timeout` (숫자)
- **범위**: `core.py` (`read_config`, `up`), `panel.py`, 문서의 설정 표
- **확인**: frontend → backend 의존 설정에서 backend 포트가 열린 뒤에 frontend가 시작되는지 본다.

### 10. 좁은 폭에서 화면 깨짐

- **현상**: 대시보드 폭이 약 28칸보다 좁으면 서비스 행이 화면 폭을 넘고, 터미널 자동 줄바꿈 때문에 화면이 깨진다. 이름 열 최소 폭(6)에 고정 열을 더한 값이 폭보다 커지기 때문이다.
- **개선안**: 폭에 따라 열을 줄인다.
  - 40칸 미만: 포트 열을 숨긴다.
  - 30칸 미만: 상태를 아이콘만 표시한다.
  - 모든 줄을 마지막에 화면 폭으로 한 번 더 자르는 안전장치를 둔다.
- **범위**: `panel.py` (`draw`)
- **확인**: pane 폭을 20~40칸으로 줄여 가며 깨지지 않는지 본다.

### 14. 실행되지 않는 코드 정리

- `term.py`의 `_UnixTerminal.read`에 있는 `except InterruptedError`는 실행되지 않는다. Python 3.5+(PEP 475)는 시그널 처리 후 `select`를 자동으로 다시 실행하기 때문이다. 크기 변경은 `SIGWINCH` 핸들러가 세운 플래그로 다음 읽기 때 처리된다.
- 해당 분기를 지우고 주석으로 이유를 남긴다.

### 15. 설정 파일 실행 관련 보안 안내

- `.herdr-devrun.json`의 `command`는 그대로 셸에 입력된다. 남의 저장소를 받아 `up`을 실행하면 그 저장소가 정한 명령이 실행된다(npm scripts, Makefile과 같은 성격).
- [usage.md](usage.md)와 README에 "처음 받은 저장소는 실행 전에 설정 파일 내용을 확인한다"는 안내를 추가한다.
- 실행 전에 확인을 받는 기능(처음 보는 설정 파일이면 대시보드에서 명령 목록을 보여 주고 승인)은 필요하면 따로 검토한다.
