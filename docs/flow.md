# 흐름도

herdr-devrun 의 주요 동작을 흐름도로 정리합니다. 그림은 Mermaid 로 적었으므로 GitHub 나 Mermaid 를 지원하는 편집기에서 보입니다.

- 세부 설정 항목은 [usage.md](usage.md) 를 봅니다.
- 상태 저장과 모듈 구조는 [architecture.md](architecture.md) 를 봅니다.

## 1. 설정 파일 찾기

액션을 실행한 pane 의 폴더에서 위로 올라가며 `.herdr-devrun.json` 을 찾습니다. 못 찾으면 오류입니다.

```mermaid
flowchart TD
    A[액션 실행: up / down / restart / panel] --> B[포커스된 pane 의 폴더 확인]
    B --> C{이 폴더에 .herdr-devrun.json 이 있나?}
    C -- 있음 --> F[설정 파일 사용]
    C -- 없음 --> D{상위 폴더가 남아 있나?}
    D -- 있음 --> E[한 단계 위로] --> C
    D -- 없음 --> X[오류: 설정 파일 없음]
    F --> G[설정 검증]
    G -- 실패 --> X2[오류 알림: 파일 경로와 문제]
    G -- 성공 --> H[다음 단계로]
```

## 2. 서비스 시작 (`up` / `run`)

실행 중인 서비스는 건너뛰고, 나머지를 `depends_on` 순서대로 시작합니다.

```mermaid
flowchart TD
    A[up 실행] --> B{모든 서비스가 실행 중인가?}
    B -- 예 --> T[그 탭으로 전환] --> Z[끝]
    B -- 아니오 --> C[실행 중이 아닌 서비스 목록]
    C --> D{의존 서비스가 준비됐나?}
    D -- 아니오, start_timeout 전 --> W[대기] --> D
    D -- 아니오, 시간 초과 --> F1[실패 기록: 의존 서비스 대기 시간 초과]
    D -- 의존 실패 --> F2[실패 기록: 의존 서비스 실패]
    D -- 예 --> P{configured port 가 이미 사용 중?}
    P -- 예 --> F3[이 서비스만 건너뜀: port in use]
    P -- 아니오 --> S[pane 에 명령 입력]
    S --> R{herdr 가 pane 생성에 성공했나?}
    R -- 아니오 --> RB[새로 만든 탭 또는 pane 닫기, 상태 되돌리기] --> F4[실패 기록]
    R -- 예 --> Q[상태 파일에 pane id 기록]
    Q --> N{남은 서비스가 있나?}
    F1 --> N
    F2 --> N
    F3 --> N
    F4 --> N
    N -- 있음 --> D
    N -- 없음 --> M{실패가 있었나?}
    M -- 있음 --> Msg[알림: 실패한 서비스 목록]
    M -- 없음 --> OK[알림: 서비스 N개 시작]
```

## 3. 서비스 중지 (`down`)

각 pane 에 Ctrl+C 를 보내고, 프로세스가 끝날 때까지 `stop_timeout` 만큼 기다린 뒤 탭을 닫습니다.

```mermaid
flowchart TD
    A[down 실행] --> B[상태 파일에서 서비스 pane 목록]
    B --> C[각 pane 에 Ctrl+C]
    C --> D{프로세스가 종료됐나?}
    D -- 아니오, stop_timeout 전 --> D
    D -- 아니오, 시간 초과 --> E[종료 안 됨 기록]
    D -- 예 --> F[다음 pane]
    E --> F
    F --> G{남은 pane 이 있나?}
    G -- 있음 --> C
    G -- 없음 --> H[탭 닫기]
    H --> I[상태 파일 정리]
```

`restart` 는 `down` 을 한 뒤 `up` 을 실행합니다.

## 4. 대시보드 (`panel`)

대시보드는 1초마다 상태를 다시 읽고, 설정 파일이 바뀌면 다시 불러옵니다.

```mermaid
flowchart TD
    A[panel 실행] --> B{같은 프로젝트 대시보드가 이미 있나?}
    B -- 있음 --> C[그 탭으로 전환] --> Z[끝]
    B -- 없음 --> D[오른쪽에 pane 을 나눠 대시보드 실행]
    D --> E[설정 읽기 · 상태 읽기]
    E --> L{입력 이벤트}
    L -- 주기 갱신 1초 --> E
    L -- 방향키 · 마우스 선택 --> E
    L -- Enter · r · a · x · o --> X[시작 · 중지 · 재시작 · 브라우저 등]
    L -- e 설정 --> Y[설정 파일을 OS 기본 프로그램으로 열기]
    L -- 추가 · 수정 · 삭제 --> FM["폼 흐름 (5 참고)"]
    L -- q · Esc --> Q[대시보드 종료, 서비스는 그대로 둠]
    X --> E
    Y --> E
    FM --> E
```

## 5. 서비스 추가 · 수정 · 삭제 폼

추가·수정은 항목을 차례로 묻습니다. Enter 는 칸의 기본값을 받고, `-` 는 값을 비웁니다. 저장 전에 설정 전체를 검증하므로, 잘못되면 파일은 그대로 두고 입력을 기본값으로 남겨 처음부터 다시 묻습니다.

**현재 구현** (이름 → 폴더 → 명령 → 포트 → URL → 의존 서비스)

```mermaid
flowchart TD
    A{버튼} -- 추가 --> B[기본값은 비움]
    A -- 수정 --> C[선택한 서비스의 현재 값을 기본값으로]
    A -- 삭제 --> D[y 입력 확인]
    B --> E[항목을 차례로 입력]
    C --> E
    E --> F{Esc?}
    F -- 예 --> Cancel[취소]
    F -- 아니오 --> G[항목 값 확정]
    G --> H{마지막 항목?}
    H -- 아니오 --> E
    H -- 예 --> I[서비스 항목 만들기]
    I --> J{수정이고 이름이 바뀌었고 실행 중?}
    J -- 예 --> Err1[오류: 먼저 중지] --> E
    J -- 아니오 --> K[설정 검증 후 저장]
    K -- 검증 실패 --> Err2[오류 표시, 입력을 기본값으로 남김] --> E
    K -- 성공 --> Ok[저장 완료, 목록 갱신]
    D --> Y{y 입력?}
    Y -- 아니오 --> Cancel
    Y -- 예 --> R{실행 중인가?}
    R -- 예 --> Err3[오류: 먼저 중지]
    R -- 아니오 --> Del[서비스 삭제, 다른 서비스의 depends_on 에서도 제거] --> Ok
```

**계획 중** (개발 중인 3단계 선택 흐름: 분류 → 기술 → 경로와 포트)

```mermaid
flowchart TD
    A[추가] --> B[1 분류 선택]
    B --> B1[프론트엔드]
    B --> B2[백엔드]
    B --> B3[미들웨어]
    B --> B4[데이터베이스]
    B --> B5[기타]
    B1 --> C[2 기술 선택]
    B2 --> C
    B3 --> C
    B4 --> C
    B5 --> C
    C --> P[프리셋에서 기본 명령과 포트를 채움]
    P --> D[3 경로와 포트 입력]
    D --> E{Enter: 기본값 · -: 비우기}
    E --> F[설정 검증 후 저장]
    F -- 검증 실패 --> D
    F -- 성공 --> G[목록 갱신]
```

프리셋은 언어와 기술별 기본 포트와 실행 명령을 담습니다. React(Vite) 처럼 포트를 고정하지 않는 기술은 기본 포트를 비워 둡니다.
