# 흐름도

herdr-devrun 의 주요 동작을 흐름도로 정리합니다. 그림은 Mermaid 로 적었으므로 GitHub 나 Mermaid 를 지원하는 편집기에서 보입니다.

- 세부 설정 항목은 [usage.md](usage.md) 를 봅니다.
- 상태 저장과 모듈 구조는 [architecture.md](architecture.md) 를 봅니다.

## 1. 설정 파일 찾기

액션을 실행한 pane 의 폴더에서 위로 올라가며 `.herdr-devrun.json` 을 찾습니다. 못 찾으면 오류입니다.

```mermaid
flowchart TD
    A[액션 실행: up / down / restart / panel] --> B[포커스된 pane 의 폴더 확인]
    B --> C{이 폴더에 .herdr-devrun.json 이 있나?}
    C -- 있음 --> F[설정 파일 사용]
    C -- 없음 --> D{상위 폴더가 남아 있나?}
    D -- 있음 --> E[한 단계 위로] --> C
    D -- 없음 --> X[오류: 설정 파일 없음]
    F --> G[설정 검증]
    G -- 실패 --> X2[오류 알림: 파일 경로와 문제]
    G -- 성공 --> H[다음 단계로]
```

## 2. 서비스 시작 (`up` / `run`)

실행 중인 서비스는 건너뛰고, 나머지를 `depends_on` 순서대로 시작합니다.

```mermaid
flowchart TD
    A[up 실행] --> B{모든 서비스가 실행 중인가?}
    B -- 예 --> T[그 탭으로 전환] --> Z[끝]
    B -- 아니오 --> C[실행 중이 아닌 서비스 목록]
    C --> D{의존 서비스가 준비됐나?}
    D -- 아니오, start_timeout 전 --> W[대기] --> D
    D -- 아니오, 시간 초과 --> F1[실패 기록: 의존 서비스 대기 시간 초과]
    D -- 의존 실패 --> F2[실패 기록: 의존 서비스 실패]
    D -- 예 --> P{configured port 가 이미 사용 중?}
    P -- 예 --> F3[이 서비스만 건너뜀: port in use]
    P -- 아니오 --> S[pane 에 명령 입력]
    S --> R{herdr 가 pane 생성에 성공했나?}
    R -- 아니오 --> RB[새로 만든 탭 또는 pane 닫기, 상태 되돌리기] --> F4[실패 기록]
    R -- 예 --> Q[상태 파일에 pane id 기록]
    Q --> N{남은 서비스가 있나?}
    F1 --> N
    F2 --> N
    F3 --> N
    F4 --> N
    N -- 있음 --> D
    N -- 없음 --> M{실패가 있었나?}
    M -- 있음 --> Msg[알림: 실패한 서비스 목록]
    M -- 없음 --> OK[알림: 서비스 N개 시작]
```

## 3. 서비스 중지 (`down`)

각 pane 에 Ctrl+C 를 보내고, 프로세스가 끝날 때까지 `stop_timeout` 만큼 기다린 뒤 탭을 닫습니다. 기다리는 동안 Y/N 질문이 나오면 `Y`로 답합니다.

```mermaid
flowchart TD
    A[down 실행] --> B[상태 파일에서 서비스 pane 목록]
    B --> C[각 pane 에 Ctrl+C]
    C --> D{프로세스가 종료됐나?}
    D -- 아니오, stop_timeout 전 --> D
    D -- 아니오, 시간 초과 --> E[종료 안 됨 기록]
    D -- 예 --> F[다음 pane]
    E --> F
    F --> G{남은 pane 이 있나?}
    G -- 있음 --> C
    G -- 없음 --> H[탭 닫기]
    H --> I[상태 파일 정리]
```

`restart` 는 `down` 을 한 뒤 `up` 을 실행합니다.

대시보드의 중지(`Enter`)와 전체 중지(`x`)는 `down` 과 다릅니다. 프로세스만 끄고 pane 을 '중지' 표시로 남기며, 제 시간에 끝나지 않은 pane 만 닫습니다. 탭과 컨트롤 박스는 그대로 둡니다. 다시 시작하면 같은 pane 에서 명령을 다시 입력합니다.

## 4. 대시보드 (`panel`)

대시보드는 1초마다 상태를 다시 읽고, 설정 파일이 바뀌면 다시 불러옵니다.

```mermaid
flowchart TD
    A[panel 실행] --> B{같은 프로젝트 대시보드가 이미 있나?}
    B -- 있음 --> C[그 탭으로 전환] --> Z[끝]
    B -- 없음 --> D[오른쪽에 pane 을 나눠 대시보드 실행]
    D --> E[설정 읽기 · 상태 읽기]
    E --> L{입력 이벤트}
    L -- 주기 갱신 1초 --> E
    L -- 방향키 · 마우스 선택 --> E
    L -- Enter · r · a · x · o --> X[시작 · 중지 · 재시작 · 브라우저 등]
    L -- e 설정 --> Y[설정 파일을 OS 기본 프로그램으로 열기]
    L -- 추가 · 수정 --> FM["폼 흐름 (5 참고)"]
    L -- 삭제 · ⊗ 닫기 --> CF["확인 창: y 또는 버튼"]
    L -- q · Esc --> Q[대시보드 종료, 서비스는 그대로 둠]
    X --> E
    Y --> E
    FM --> E
    CF --> E
```

## 5. 서비스 추가 · 수정 · 삭제 · 닫기

- **추가**: 하단 줄의 `+ 추가`. 분류 → 기술 → 이름·폴더·명령·포트·URL·의존 순서로 묻고, 마지막에 설정 전체를 검증해 저장한다. 실패하면 파일은 그대로 두고 입력을 기본값으로 남겨 처음부터 다시 묻는다.
- **수정**: 행의 `✎ 수정`. 현재 값을 기본값으로 같은 칸을 묻는다. 실행 중인 서비스의 이름은 바꿀 수 없다.
- **삭제**: 행의 `✕ 삭제`. 확인 창에서 `y` 또는 **삭제**를 누르면 지운다. 실행 중이면 창을 띄우지 않고 하단 줄에 먼저 중지하라고 안내한다.
- **닫기**: 행의 `⊗`. 확인 창에서 `y` 또는 **닫기**를 누르면 그 서비스의 pane 을 닫는다. 실행 중이면 먼저 끈다. 탭과 컨트롤 박스는 남는다.

```mermaid
flowchart TD
    A{버튼} -- 추가 --> B[분류 → 기술 → 항목 입력]
    B --> K{마지막 항목?}
    K -- 아니오 --> B
    K -- 예 --> V[설정 검증 후 저장]
    V -- 검증 실패 --> E1[오류 표시, 입력을 기본값으로 남김] --> B
    V -- 성공 --> OK[저장, 목록 갱신]
    A -- 수정 --> F[현재 값을 기본값으로 항목 입력] --> K2{이름이 바뀌었고 실행 중?}
    K2 -- 예 --> E2[오류: 먼저 중지] --> F
    K2 -- 아니오 --> V
    A -- 삭제 --> D[확인 창] --> Y{y 또는 삭제?}
    Y -- 아니오 --> C[취소]
    Y -- 예 --> R{실행 중?}
    R -- 예 --> E3[하단 줄에 먼저 중지 안내]
    R -- 아니오 --> DEL[서비스 삭제, depends_on 에서도 제거] --> OK
    A -- 닫기 --> CF2[확인 창] --> Y2{y 또는 닫기?}
    Y2 -- 아니오 --> C
    Y2 -- 예 --> KILL{프로세스가 살아 있나?}
    KILL -- 예 --> STOP[먼저 끄기] --> PANE[pane 닫기, 상태에서 제거]
    KILL -- 아니오 --> PANE
```

프리셋은 언어와 기술별 기본 포트와 실행 명령을 담습니다. React(Vite) 처럼 포트를 고정하지 않는 기술은 기본 포트를 비워 둡니다.
